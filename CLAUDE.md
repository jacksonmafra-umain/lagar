# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

The repo holds the Python collector (`collector/`, SFS from Riksdagen open data), the static API generator (`api/`), the corpus (`corpus/`) the Compose Multiplatform app (`app/`: Android, iOS, wasmJs) and the static landing page (`landing/`, Swedish and English). The app covers onboarding, the scope-based home (Utforska), search and advanced search, Hierarki, Sparade (bookmarks), the document reader, the drawer and settings; Tjänster is a placeholder. Planning and design input:

- `lagar-implementation-prompt.md` — **the master spec**, local-only: it is excluded from git (`.git/info/exclude`) and may be missing in other clones. When present, read it before any work; it defines the monorepo layout, corpus schema, static API contract, app stack, CI workflows and milestones (M0–M12). Follow its milestone order. When missing, rely on this file, `docs/` and `DESIGN.md`, and ask the owner for anything they don't cover. Never commit it or quote it in tracked files.
- `docs/architecture.md` — app information architecture: normative-layer hierarchy, context engine, 4-tab shell (Utforska / Hierarki / Sparade / Tjänster), onboarding and navigation flows. Some features it describes go beyond the spec (reading a law as of a past date, version comparator, inline notes, GPS kommun detection); the static API in the spec does not yet expose historical text, so check with the owner before building those.
- `DESIGN.md` — the chosen design system ("Nordic Juridisk Klarhet"): M3 color roles (light + dark), layer colors, typography, radii, spacing, Liquid Glass elevation spec, Compose implementation notes. Started from `design/stitch/nordic_juridisk_klarhet/DESIGN.md` but has since been extended (dark mode, accessible layer text colors); the root file is canonical, the Stitch copy is the untouched export.
- `design/stitch/` — Google Stitch export (`code.html` + `screen.png` per screen).
- `docs/screens.md` — inventory of every app screen: route, design references, features with status, and the issue for each gap. Keep it current when a screen changes.

## Commands

Run from the repo root.

- Collect SFS: `python3 -I collector/collect.py sfs --fundamental` or `python3 -I collector/collect.py sfs --from YYYY-MM-DD --to YYYY-MM-DD [--limit N] [--since YYYY-MM-DD]`. State lives in `collector/data/sfs-state.json`; default `--rate` is 1 request/s.
- Incremental sync (what the daily `Sync SFS` workflow runs): `python3 -I collector/collect.py sfs --changed-since "YYYY-MM-DD[ HH:MM:SS]" --report build/sync-report.json`, then `sfsr --refresh --number ...` for every statute it wrote and `sfspdf --rss`. The committed marker is `collector/data/sfs-sync.json`; trigger the workflow manually with `gh workflow run sync-sfs.yml [-f since=YYYY-MM-DD]`.
- Snapshot authoritative SFS PDFs: `python3 -I collector/collect.py sfspdf --year YYYY [--limit N] [--cache sources/cache]` or `... sfspdf --rss` (incremental). Writes the committed manifest `sources/sfs-pdf-manifest.json`; PDF bytes are never committed. State lives in `collector/data/sfspdf-state.json`.
- Amendment register (SFSR): `python3 -I collector/collect.py sfsr --pilot` or `... sfsr --number YYYY:N [--number ...]` or `... sfsr --all`; fills `in_force` and `amendments` in the frontmatter of statutes already in the corpus and writes the committed manifest `sources/sfsr-manifest.json` (page SHA-256). Default `--rate` 2 s. State lives in `collector/data/sfsr-state.json`.
- EU law in Swedish (Cellar): `python3 -I collector/collect.py eu --list collector/data/eu-acts.json [--consolidated] [--cache sources/cache/eu]` or `... eu --celex 32016R0679[,...]`. Metadata via SPARQL, text via content negotiation on `publications.europa.eu`; never use `eur-lex.europa.eu`. Writes `corpus/eu/` and the committed manifest `sources/eu-manifest.json`. State lives in `collector/data/eu-state.json`. Incremental (what the daily `Sync EU` workflow runs): add `--consolidated --changed-since <marker>`; the committed marker is `collector/data/eu-sync.json`, run it by hand with `gh workflow run sync-eu.yml [-f since=YYYY-MM-DD]`. `--cache sources/cache/eu --offline --refresh` reconverts from cached bytes without network.
- Collect case law (Sveriges Domstolar, referat and notiser only): `python3 -I collector/collect.py case-law [--court HDO] [--from YYYY-MM-DD --to YYYY-MM-DD] [--since YYYY-MM-DD] [--limit N] [--report FILE]`. Writes `corpus/case-law/{reports,notices}/`; attachments and non-guiding decisions are never fetched. State lives in `collector/data/case-law-state.json`; default `--rate` 1 s. The daily `Sync case law` workflow runs `case-law --since <marker>` with the committed marker `collector/data/case-law-sync.json`; trigger it with `gh workflow run sync-case-law.yml [-f since=YYYY-MM-DD]`.
- Collect agency regulations (pilot series AFS, FFFS, TSFS): `python3 -I collector/collect.py agency --series AFS [--series FFFS ...] [--year YYYY] [--number 'AFS 2023:1'] [--limit N] [--refresh] [--report FILE]`. Writes base regulations to `corpus/agency/regulations/` and the committed PDF manifest `sources/agency-pdf-manifest.json`; honours each host's robots.txt (never fetch Arbetsmiljöverket's `/ursprungs/` PDFs). State lives in `collector/data/agency-state.json`; `--rate` at least 1 s.
- Collect county regulations (länets författningssamling, lansstyrelsen.se): `python3 -I collector/collect.py county --county 01 [--from-year YYYY] [--to-year YYYY] [--limit N] [--no-pdf] [--report FILE]`. Landing pages and layouts per county are in `collector/data/counties.json` (`pages`: HTML detail pages, Stockholm/Halland/Gävleborg; `files`: PDF links, file-share modules or year folders, the other 18). Writes `corpus/region/county-regulations/` and the committed PDF manifest `sources/county-pdf-manifest.json` (size and SHA-256; bytes never kept). State lives in `collector/data/county-state.json`; `--rate` at least 1 s. The weekly `Sync county regulations` workflow (`sync-county.yml`) collects the current and previous year for every county.
- Municipal regulations (kommunala författningssamlingar): `python3 -I collector/collect.py municipal --kommun 0180 [--kommun 1480 ...] [--limit N] [--report FILE]` or `... municipal --all`. Driven by `collector/data/municipalities.json` (kommun code → listing URLs, hosts and an `html_index` or `domino_view` strategy; see `collector/README.md` for adding a kommun). Only rules that bind residents; internal governance documents are excluded. robots.txt is read per host with wildcard support; disallowed PDFs are recorded as gaps. Writes `corpus/municipality/regulations/` and the committed manifest `sources/municipal-manifest.json`. State lives in `collector/data/municipal-state.json`.
- Metadata-only amendment history: `python3 -I collector/history.py --pilot --dry-run`, or `--out build/history.fi` and then `git fast-import --quiet < build/history.fi` (creates `history/pilot` locally; do not push it without the owner).
- Audit the corpus: `python3 -I collector/audit.py [--fsck]` writes `collector/data/pending-integrity.json`; exits 1 on schema errors, duplicate ids or path mismatches.
- Progress reports: `python3 -I collector/plan.py` reads `collector/data/targets.json` and the audit JSON, writes `PROGRESS.md` and `progress.svg`, and rewrites the per-layer table in `README.md` between the `<!-- progress:start -->` and `<!-- progress:end -->` markers (the sync workflows commit it with the other reports). Run the audit first; `COVERAGE.md` is hand-written.
- Kommun centroids for the app's location suggestion: download SCB's CC0 boundaries zip once (URL in `collector/lagar/centroids.py`) and run `python3 -I collector/centroids.py <zip>`; it rewrites `app/shared/src/commonMain/composeResources/files/geo/sweden.json` with `lat`, `lon` and `radiusKm` per kommun.
- Agencies and sources log: `python3 -I collector/agencies.py [--refresh]` writes `AGENCIES.md`, `collector/data/agencies-report.json` and the landing page catalog `landing/data/sources.json` from lagrummet.se's `rattskalla` index (every source with its official link and description, cached in `collector/data/rattskalla.json`) and the rättspraxis court list (`collector/data/courts.json`); `--refresh` fetches both again (robots.txt checked, `--rate` at least 1 s). Curated names, statuses, gap reasons and tracking issues are in `collector/data/agencies.json`, kommun websites in `collector/data/kommuner.json`; counts come from the corpus, `counties.json`, `municipalities.json` and the app's geo file. Every sync workflow regenerates it offline; the weekly `Sync agencies log` workflow (`sync-agencies.yml`) refreshes the sources. A new lagrummet.se entry shows up as unclassified until it is added to `agencies.json`.
- Build the API: `python3 -I api/build.py --corpus corpus --out build/api/v1`
- Check the API size against the GitHub Pages budget: `python3 -I api/size_report.py --api build/api/v1 [--site <dir>]`; fails above 900 MB (warns above 800 MB). `api.yml` and `pages.yml` run it and print the report to the step summary. Per-layer search index budgets live in `api/searchindex.py`.
- MCP server over the static API: `python3 -I mcp/server.py [--api build/api/v1 | https://jacksonmafra-umain.github.io/lagar/api/v1/] [--repo .]` speaks MCP over stdio (stdlib only). Tools: `search_laws` (per-layer search index), `get_document`, `list_layers`, `list_documents` and `get_report` (`PROGRESS.md`, `COVERAGE.md`, `AGENCIES.md`). `.mcp.json` registers it against `build/api/v1`; build the API first. Tests: `python3 -I -m unittest discover -s mcp/tests -t mcp`.
- Run the web app offline against local data: `python3 -I scripts/serve_local.py [--build missing|always|never] [--port 8001]` builds the API (`build/api/v1`) and the wasmJs distribution when missing, then serves the app at `/` and the API at `/api/v1/` from one server (the layout the app expects). Tests: `python3 -I -m unittest discover -s scripts/tests -t scripts`.
- Collector tests: `python3 -I -m unittest discover -s collector/tests -t collector` (single test: add `-k <name>`)
- API tests: `python3 -I -m unittest discover -s api/tests -t .`
- Landing page: tests `python3 -I -m unittest discover -s landing/tests` and `node --test landing/tests/lang.test.cjs landing/tests/catalog.test.cjs`; `scripts/build-site.sh` builds the web app and assembles `build/landing/` (landing page, fonts, web app under `app/`). The `Site` workflow (`.github/workflows/site.yml`) deploys it to Vercel (project `lagar`, <https://grundlagar.vercel.app>): a preview per PR, production on `main`. `landing/vercel.json` proxies `/app/api/v1/*` to the API on GitHub Pages. Do not use a top-level `site/` folder: `pages.yml` uses it as scratch output.

- App (`app/`, needs JDK 21 and `ANDROID_HOME`; see `app/README.md` for the local API server and per-platform data source):

  ```sh
  ./gradlew :androidApp:assembleDebug
  ./gradlew :webApp:wasmJsBrowserDistribution
  xcodebuild -project iosApp/iosApp.xcodeproj -scheme iosApp -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' build
  ```

  Serve the built API locally with `python3 -m http.server 8000 -d build`. Release builds read the published API at `https://jacksonmafra-umain.github.io/lagar/api/v1/`; the `Pages` workflow (`.github/workflows/pages.yml`) deploys the API and the web app there on every push to `main` that touches `corpus/`, `api/` or `app/`.

- Lint: `uvx ruff check collector api mcp scripts` (config in `ruff.toml`) and `./gradlew ktlintCheck` / `ktlintFormat` from `app/` (rules in `.editorconfig`). `pre-commit install` enables the hooks in `.pre-commit-config.yaml` (whitespace, ruff, corpus frontmatter audit, ktlint).
- CI: `collector.yml` (ruff, tests on Python 3.12/3.13), `api.yml` (tests, corpus audit, full API build, size budget), `tools.yml` (ruff, MCP server and local server tests) and `app.yml` (ktlint, build-logic and shared tests on the JVM and wasmJs, Android debug APK, wasmJs build, iOS simulator build) run on PRs and on `main` for their paths; `pages.yml` deploys, `sync-sfs.yml`, `sync-case-law.yml` and `sync-eu.yml` sync the corpus daily, `sync-county.yml` syncs county regulations weekly and `sync-agencies.yml` refreshes the agencies log weekly.

Workflow: work goes through labelled GitHub issues and PRs assigned to the owner, merged into `main`.

## What lagar is

Swedish legislation, case law, EU law, municipal regulations and public services as one YAML-fronted Markdown file per norm (`corpus/`), built by a Python collector, turned into a static JSON API on GitHub Pages (`api/`), and consumed by a Compose Multiplatform app (`app/`: Android, iOS, wasmJs SPA). Sister project of the Brazilian corpus <https://github.com/jacksonfdam/leis>; reuse its ideas (closed type vocabulary, resumable rate-limited collectors, SHA-256 source snapshots, generated progress files, `git fast-import` history reconstruction).

Planned data flow: `collector/` (Python, `python3 -I`, stdlib first) → `corpus/*.md` + `sources/` snapshots → `api/` generator → `/api/v1/*.json` → app. The app depends only on the API contract (`docs/api.md`), never on the corpus directly. Corpus history is rebuilt on a dedicated branch as one commit per amendment, dated at entry into force.

## Hard rules from the spec

- Everything in English (code, identifiers, frontmatter keys, file names, commits, docs). Only legal texts and Swedish UI strings are in Swedish. Never machine-translate legal text in the app.
- No mention of any AI/assistant/tool in commits, trailers, PRs, README, comments or file headers.
- Micro commits, Conventional Commits (`feat(collector):`, `fix(app):`, `data(sfs):`, `chore(ci):`, `docs:`, `test:`); each commit builds and passes tests.
- i18n from day one: Compose resources, `values/` = English base, `values-sv/` = Swedish, app defaults to Swedish when system locale unsupported. No hardcoded user-facing strings.
- Collectors: rate-limited, resumable, idempotent, honour `robots.txt`, descriptive User-Agent with repo URL, never bypass blocks/captchas/paywalls (record as coverage gap). Case law: anonymised versions only.
- Pin latest stable Kotlin / CMP / AGP / Gradle / Ktor via a version catalog.
- No user accounts or BankID sign-in for now (owner decision). The app is anonymous; bookmarks and settings stay on the device. The Swedish Stitch screen still shows BankID — ignore that element.
- Stop and ask the owner when: the Stitch export is missing or ambiguous, `gh` is authed to an account other than the owner's Umain account (`jacksonmafra-umain`), a source forbids automation, or Stitch conflicts with accessibility/i18n.

## Design input caveats

- Most screens in `design/stitch/` are from the Brazilian **leis.org** project (`lang="pt-BR"`, Brazilian states/municipalities, Portuguese labels). Treat them as layout/component references only; translate concepts to the Swedish model (Nationell / Region / Kommun scopes, Swedish layer names). Only `lagar_normhierarki_f_rgsystem/` is Swedish.
- `design/stitch/juris_glass_system/DESIGN.md` is an alternative system; the root `DESIGN.md` (Nordic Juridisk Klarhet) is the one to implement.
- Layer colors live in the `layers:` frontmatter of `DESIGN.md` (base values match the spec's fallback palette); every chromatic accent maps to a normative layer. Each layer has `base` (light icons/borders/tints), `text` (light-mode text, AA-safe) and `dark` (all dark-mode uses). Never put text in a `base` color — six bases fail contrast. Badges/surfaces use 10–12% alpha of the layer color (14–16% in dark), 20% alpha border.
- The spec's `layer` field has one `sfs` value, but the palette splits SFS acts and ordinances: pick the color from `type`.
- Typography: Inter for UI chrome, Source Serif 4 for legal text; § numbers bold Inter.
- Theme lives in `app/shared/.../designsystem/` (`LagarTheme`, `LagarColors`, `LagarTypography`, `LagarSpacing`, shapes), light + dark; write `docs/design.md` inventory before UI code.
