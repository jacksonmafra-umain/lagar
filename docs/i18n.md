# Internationalisation

The app ships Swedish and English. Strings live in Compose resources
(`app/shared/src/commonMain/composeResources/`): `values/` is the English base and
`values-sv/` is Swedish.

## How the locale is resolved

1. The user's setting (`LanguageChoice`: `System`, `Swedish`, `English`) is stored by
   `UserPreferences` on the device.
2. `System` resolves with `SupportedLanguage.resolve(systemLanguageTag())`: a system language of
   `sv` or `en` is used as is, anything else (for example `de-DE`) becomes Swedish. Explicit
   choices map directly.
3. `ProvideAppLocale(language)` forces the platform resource locale to the result and recomposes
   its content when it changes, so switching language needs no restart. It is required because
   `values/` is English: relying on resource fallback would show English for unsupported locales.

Per platform (`ProvidePlatformLocale` / `systemLanguageTag`):

- Android: `Locale.setDefault` plus a `Configuration` provided through `LocalConfiguration`. The
  system tag is the default locale captured before the first override.
- iOS: writes `AppleLanguages` in the app's `NSUserDefaults`. The system tag is read from the
  `NSGlobalDomain` entry, so it stays correct after a restart with a persisted override.
- Web: overrides `navigator.language` and `navigator.languages`; the real value is kept in
  `window.__lagarSystemLanguage`.

## Adding a language

One `values-xx` folder with a complete `strings.xml`, and one `SupportedLanguage` entry
(`Name("xx")`). Add a `LanguageChoice` entry and its mapping in `LanguageChoice.resolve` if the
language should be selectable in settings.

## Rules

- No hardcoded user-facing strings; every string goes in both `strings.xml` files.
- No sentence concatenation; use format arguments and plurals.
- Legal text is never translated: it is shown exactly as the API returns it, in its own language.
